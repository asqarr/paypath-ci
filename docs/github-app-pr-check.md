# GitHub App PR Check Vertical Slice

This package is the first GitHub-native PayPath integration. It authenticates signed GitHub App webhook deliveries, queues supported pull request events, and publishes a **neutral** or **action required** Check Run against the exact current PR head SHA. It does not run billing checks, inspect Stripe or Supabase, or execute code from a pull request.

The Check summary is deliberately explicit:

> GitHub integration verified. Customer billing tests are not configured or executed.

The result must not be described as a billing PASS.

## App registration and least-privilege permissions

Create a GitHub App manually for an isolated test repository. This repository does not create, register, or install an App for you.

Configure only:

- Repository permission **Checks: Read and write** to create and complete Check Runs.
- Repository permission **Pull requests: Read-only** to verify that a queued event still refers to the current PR head SHA.
- **Metadata: Read-only**, which GitHub requires for repository access.
- Subscribe to the **Pull request** webhook event only.
- Install the App only on a disposable test repository during the pilot.

Do not grant Contents, Actions, Administration, Issues, or Organization permissions. Do not subscribe to `push`, `check_run`, or unrelated events. App private keys and webhook secrets are backend-only.

## Local configuration and run

Use Node.js 24. Copy the placeholder-only template and fill it locally; the destination is ignored by Git:

```powershell
Copy-Item docs/github-app.env.example .env.github-app.local
```

Set these values in `.env.github-app.local`:

| Variable | Purpose |
| --- | --- |
| `PAYPATH_GITHUB_APP_ID` | Numeric GitHub App ID |
| `PAYPATH_GITHUB_PRIVATE_KEY` | Private key PEM generated by GitHub; escaped `\n` sequences are accepted |
| `PAYPATH_GITHUB_WEBHOOK_SECRET` | Secret configured on the App's webhook settings |
| `PAYPATH_GITHUB_PORT` | Optional local port; defaults to `8787` |
| `PAYPATH_GITHUB_HOST` | Optional bind address; defaults to `127.0.0.1` |

The checked-in example contains placeholders, not credentials. Never commit a filled environment file or paste a private key or webhook secret into a PR, issue, chat, or log. No Stripe or Supabase credentials are needed for this integration slice.

Install and run:

```powershell
npm ci
npm run dev:github-app
```

The local endpoints are `GET http://127.0.0.1:8787/healthz` and `POST http://127.0.0.1:8787/webhooks/github`. The process binds to loopback by default. For a real GitHub delivery, configure a publicly reachable HTTPS endpoint that you control and route it to the webhook path; do not expose the development server directly to the public internet.

## Connect an isolated test repository

1. Create the App in your own GitHub account or organization and apply only the permissions above.
2. Set its webhook URL to your controlled HTTPS receiver plus `/webhooks/github`; set a strong webhook secret and keep the same value only in your local/server environment.
3. Generate a private key in the App settings and place it in the ignored environment file or a managed secret store.
4. Install the App only on a disposable repository with no customer data.
5. Start the backend and open a test PR in that repository. The App should receive `opened`, `synchronize`, or `reopened`, verify the signature, enqueue the PR identity, and create a Check Run named **PayPath CI / Billing Safety**.
6. Confirm the Check Run SHA equals the PR's current head SHA. The conclusion will be `neutral` for same-repository PRs and `action_required` for fork PRs. Neither conclusion is a billing PASS.

The App does not check out, build, import, or execute PR code. Fork PRs are marked untrusted and receive an `action_required` result; the integration still only reads PR metadata and writes the Check Run through the installation token.

## Local tests without GitHub credentials

All GitHub App tests use synthetic payloads, an in-memory queue, and a fake GitHub API. They generate test HMAC signatures locally and make no external GitHub request:

```powershell
npm run test:github-app
npm test
npm run typecheck
npm run build
npm run test:pr-gate
node scripts/standalone-cli-smoke.mjs
```

The tests cover signed and unsigned webhook bodies, malformed payloads, supported and ignored events, exact SHA handling, duplicate and out-of-order deliveries, forks, stale PR heads, API errors, and secret-safe diagnostics. A valid local signature proves only the verifier's behavior; it does not verify a real App installation or GitHub delivery.

## Queue and operational limits

The current `InMemoryJobQueue` is a development adapter. A repeated `X-GitHub-Delivery` is rejected; execution keys deduplicate the same repository/PR/head-SHA, while a valid `reopened` lifecycle gets a fresh execution key for its pull-request update timestamp. Concurrent deliveries for that same reopen lifecycle collapse to one run. The worker re-reads the PR head before creating a Check Run so an old event cannot label a newer commit. All delivery and execution idempotency state is process-local: separate instances do not coordinate and can create duplicate Check Runs. State is lost on restart, there is no durable retry/dead-letter handling, and a process crash can lose queued work. **This adapter is not production-ready.** A deployment must supply a durable queue and shared idempotency store with safe retry handling before customer use.

GitHub API requests have a 10-second timeout. Logs include only operation, error type, HTTP status, and a validated GitHub request ID where available; they do not include raw error messages, payloads, headers, tokens, or private keys. No Billing Core, Stripe adapter, Supabase adapter, or customer credentials are loaded by this package.

Implementation references: [GitHub webhook signature validation](https://docs.github.com/en/webhooks/using-webhooks/validating-webhook-deliveries), [GitHub Check Runs API](https://docs.github.com/en/rest/checks/runs), and [Octokit's GitHub App authentication](https://github.com/octokit/auth-app.js).

## Validation boundary

The unit and local HTTP tests do not contact GitHub. No GitHub App has been registered or installed for this project, and real App authentication, repository installation scope, webhook delivery, Check Run visibility, and fork behavior remain **NOT VERIFIED** until an operator configures an isolated test App and repository.
